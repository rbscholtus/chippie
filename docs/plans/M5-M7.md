# Chippie: implementation plans for M5 and M7

## Context

M1–M4 give a tested CHIP-8 core, the Ebitengine shell, and the catalogue and
library. M4 is on `m4-catalogue`, with uncommitted work. SUPER-CHIP and XO-CHIP
ROMs are about 37% of the database (105 + 97 of 543), but still show as
"coming soon". This plan adds both platforms in the same shape as
[M1-M4.md](M1-M4.md): each milestone ends working, with
all its tests green.

**Order: M5 → M7 → M6 → M8 works. M7 does not need M6.**

| Dependency | Kind | Handling |
|---|---|---|
| M4 → M5 | Hard | Finish and merge M4 first; M5 flips `Implemented` and edits files M4 has changed |
| M5 → M7 | Hard | XO-CHIP reuses hi-res, scrolling, DXY0, big font and the opcode gating |
| M6 → M7 | None | M7 touches `chip8/`, `app/sound/` and one renderer setter; M6 is skin, knobs and layout |
| M7 → M6 | Soft (two seams) | Volume knob must cover the pattern voice too: M7 keeps one voice behind `sound.Output`. Tint knob needs palettes: M7 adds `Renderer.SetPalette` for it to use |
| M7 → M6 | Benefit | M6's "CRT at 60 FPS on iPhone" can then be measured with hi-res and 2-plane games |
| M5, M7 → M8 | Soft | §18 confirms platforms by running the ROMs. M8 does not need M6 |

Decisions made while planning:

- **SUPER-CHIP behaviour:** modern by default, which is what the database's
  `superchip` quirks describe. A new `Quirks.LegacySuperChip`, off by default
  and switchable per ROM, adds the HP48 behaviours.
- **ROM colours:** applied in M7, so XO-CHIP planes aren't grey until M6.
- **Zophar ROMs:** downloaded once during M5 and kept only where the SHA-1
  matches the database.
- **RPL flags (FX75/FX85):** held in memory and cleared on `Reset`. Saving them
  across sessions is left out; it could later use per-ROM prefs.

**First step:** save this plan as `docs/plans/M5-M7.md` and link it from README
§19.

**Definition of done (both milestones):** as in M1-M4: lint native and
`GOOS=js GOARCH=wasm` with no bare `//nolint`, `go test -race ./...`, native and
WASM builds, Playwright, README/CONTRIBUTING updated, Conventional Commits,
benchstat output for `chip8/` and `app/crt/` changes. Branches `m5-superchip`
and `m7-xochip`, off `main`.

## M5: SUPER-CHIP

**Goal:** `chip48`, `superchip1` and `superchip` run. All SCHIP quirk and
scrolling tests pass, modern and legacy. The 12 Zophar ROMs are hosted.

### Core (`chip8/`)

- **`platform.go`:** add an opcode-set bitmask to `platformInfo`, cached on
  `Machine` at `Reset`. This is the permitted "does this opcode exist" check.
  - `chip48`: base only.
  - `superchip1`: `00FD 00FE 00FF DXY0 FX30 FX75 FX85`.
  - `superchip`: those plus scrolling `00CN 00FB 00FC`.
  - Set `implemented: true` on all three.
- **`quirks.go`:** add `LegacySuperChip`, documented as not coming from
  `quirks.json`. Effects:
  - lo-res display wait (`DXYN` ends the frame in lo-res only);
  - lo-res pixels are 2×2 and scrolling moves physical pixels;
  - lo-res `DXY0` is 8×16 (modern: 16×16);
  - hi-res `VF` counts rows that collided or were clipped at the bottom
    (modern: 0/1);
  - `00FE`/`00FF` don't clear the screen (modern: they clear).
- **`display.go`:**
  - Add `scale`. Legacy lo-res uses the 128×64 buffer at scale 2; every other
    case stays scale 1 at the active resolution.
  - Scroll always works on buffer pixels, so one implementation gives both the
    modern and legacy amounts.
  - Generalise `drawSprite` to take a width of 8 or 16.
  - `DisplayView` reports the buffer size, so legacy lo-res is 128×64 and the
    renderer needs no change. It already reallocates on a resolution change.
- **`ops_schip.go`:** the opcodes above, with `FX75/85` limited to `X ≤ 7`.
  `00FD` halts with a new sentinel `ErrProgramExit`.
- **`fonts.go`:** 16-glyph big font at a named address after the small font.
- **`disasm.go`:** use the `p` parameter to select the opcode set.
- **`cpu.go`:** route `0x0` and `DXY0` through the gated cases.

### Settings and catalogue

- `catalogue/profile.go` and `app/settings.go`: carry `LegacySuperChip` in
  `Overrides`, shown only for SUPER-CHIP platforms.

### Hosted ROMs

- Download the Zophar packs into the scratchpad and keep the 12 hash-matching
  files in `web/hosted-roms/` with `.DOC` files and attribution. Record them in
  `assets/LICENSES.md`.
- `cmd/catalogue-gen`: hash that folder and emit source `chippie` with relative
  URLs `roms/hosted/<file>`. `catalogue.Sources` and `romstore`'s `base` already
  support this and try it last. Add a row to the coverage report.
- `scripts/build.sh`: copy to `$out/roms/hosted/`.
- `app/roms` `LoadHash`: read the same folder on native builds, where relative
  URLs can't be fetched.

### Tests

- Table-driven tests for every new opcode × `LegacySuperChip`, opcode gating per
  platform, and scroll edge cases; `BenchmarkDXYN/hires`, `BenchmarkScroll`.
- `cmd/golden-import`: add `hires-scrolling` and `hires-no-scrolling` at 128×64.
- `suite_test.go`: tests 1–4, 6, 7 on the three new platforms, plus:

| Test | `0x1FF` | Profile | Golden |
|---|---|---|---|
| 5-quirks | 2 | `superchip` | generated, checked by eye |
| 5-quirks | 4 | `superchip` + legacy | generated, checked by eye |
| 8-scrolling menu | — | `superchip` | imported |
| 8-scrolling lo-res | 1 | `superchip` | imported |
| 8-scrolling lo-res half | 2 | `superchip` + legacy | imported, via `testrig.Halve` |
| 8-scrolling hi-res | 3 | `superchip` | imported |

- `testrig.Halve`: reduces 128×64 to 64×32 and fails on any non-uniform 2×2
  block. `suiteCase` gains `halve`, `quirks` and an optional tick override, in
  case the quirks test reports `SLOW` at 30 ticks.
- Generated quirk goldens must show every check passing. If one doesn't, fix the
  emulator; never accept the frame.
- catalogue-gen fixture test; every hosted file has a manifest entry.
- Update the tests that use Turnover '77 as "coming soon"
  (`app/library/library_test.go`, `app/game_test.go`); use an XO-CHIP game.
- e2e: Turnover '77 starts and draws in hi-res.

**Done when:** README's M5 row holds, and Octopeg, Turnover '77 and a hosted ROM
play in the browser.

## M7: XO-CHIP

**Goal:** `xochip` runs with both planes, 64 KB and pattern audio. Quirks and
scrolling tests pass.

### Core (`chip8/ops_xochip.go`, `display.go`, `cpu.go`)

- Set `implemented: true`, add the XO opcode set (includes SCHIP's). The table's
  64 KB and 2 planes already exist.
- State: `plane` (default 1), `pattern [16]byte`, `patternLoaded`, `pitch`
  (default 64), all set at `Reset`.
- Opcodes:
  - `00DN` scroll up;
  - `5XY2`/`5XY3` save/load `VX..VY`, either direction, `I` unchanged;
  - `F000 NNNN` long `I`;
  - `FN01` select planes;
  - `F002` load pattern;
  - `FX3A` pitch.
- `skip()` steps over 4 bytes when the next opcode is `F000` on XO-CHIP.
- `DXYN` draws per selected plane, with sprite data consecutive; collision is
  any plane; plane 0 draws nothing. Read memory directly, since two 16×16 planes
  exceed `maxSpriteRows`.
- `00E0` and scrolling affect selected planes only, by masking plane bits in the
  existing routines. `00FE`/`00FF` clear the screen. `FX75/85` allow all 16.
- `disasm.go`: XO mnemonics; `F000` shows without its operand, since a
  `TraceEntry` holds one word.

### Audio (`app/sound`)

- `SoundState` gains `Pattern [16]byte`, `Pitch byte`, `HasPattern bool`,
  returned by value with no allocation.
- `Buzzer` becomes one voice with two sources, so M6's volume has one place to
  act. With a pattern it plays the 128 bits MSB-first at
  `4000 × 2^((pitch-64)/48)` Hz, keeping phase across updates and reusing the
  existing ramp; otherwise the existing 440 Hz square.
- XO ROMs that never run `F002` keep the plain buzzer.
- `Set` shares state with the audio goroutine under a short mutex; `Read`
  snapshots at the start of each call.

### Colours

- `Renderer.SetPalette` in `app/crt/renderer.go`, with a small parser for
  `catalogue.Colors` in `app/crt`. It takes 2- or 4-entry palettes and falls back
  to `DefaultPalette` on anything unparseable.
- Applied when a game loads in `app/game_flow.go`, and reset for the next game.

### Tests

- Table-driven opcode tests: each plane mask for draw, clear and scroll, 4-byte
  skip, `5XY2/3` both directions, top-of-memory wrap.
- `BenchmarkDXYN/xo-2planes`; `BenchmarkRunFrame/xochip` with a busy ROM.
- Suite: tests 1–4, 6, 7 on `xochip`, plus 5-quirks `0x1FF=3`, 8-scrolling
  `0x1FF=4,5`. Goldens are generated and checked by eye: the suite's XO test
  draws a fourth (up) arrow that its SCHIP-only pictures don't show.
- `app/sound`: pattern bits, pitch formula at 64 and at the extremes, fallback
  without a pattern, whole frames, no clicks on change.
- Palette parser and fallback in `app/crt/framebuffer_test.go`.
- Update "coming soon" tests to use a platform still unimplemented (`megachip8`
  or `hybridVIP`).
- e2e: Red October starts and shows more than two colours.

**Done when:** README's M7 row holds, and Red October and An Evening to Die For
play with correct colours and pattern audio, checked by ear in a browser.
