# Chippie: implementation plans for M1–M4

## Context

The design is complete (README.md, CONTRIBUTING.md), and the project has its
module, lint config, prototype and test-suite submodule. No code exists yet.
This plan breaks milestones M1–M4 (README §19) into concrete work. Each
milestone ends with a working implementation **and** all of its tests green:
lint (native + `GOOS=js GOARCH=wasm`), `go test -race ./...`, and the native
and WASM builds.

Decisions made while planning:

- **M1/M2 ordering:** M1 includes a minimal test rig and golden import, because
  M1's "done when" needs Timendus screenshot tests. M2 completes the rig.
- **GitHub:** the repo will be `rbscholtus/chippie`. CI starts in M1 and Pages
  deploys in M3. The repo is created and pushed only when you confirm.
- **Bundled ROMs (M3):** six chip8Archive games, all CC0, compiled in with
  `go:embed`: Glitch Ghost and Danm8ku (CHIP-8), Turnover 77 and Octopeg
  (SCHIP), Red October and An Evening to Die For (XO-CHIP). The SCHIP and
  XO-CHIP games show as "coming soon" until M5/M7.
- **Licence:** Chippie stays BSD-3. The Timendus ROMs (GPLv3) are never
  compiled in. They ship as separate files next to the WASM, with their licence
  and source link, and native builds read them from `third_party/`.
- **M4 scope** also includes `cmd/catalogue-gen` + `refresh.yml`, the
  background metadata refresh at startup, the settings panel with per-ROM
  overrides, and the chip8Archive metadata merge.

- **Allocations:** the aim is *few* allocations in the per-frame path, not
  zero at any cost. Code stays straightforward. Benchmarks report allocations
  (`b.ReportAllocs()`), and optimisation happens later, when a profile shows
  it's needed. There are no CI-failing zero-alloc tests.
- **Memory is sized per platform:** `Reset` allocates memory for the
  platform: 4 KB for CHIP-8, 64 KB for XO-CHIP later. It reuses the existing
  buffer when the size is unchanged. The display is likewise sized to the
  platform's largest resolution.

**Order of work:** implement M1 now. You review M2–M4 in the meantime.

**First step:** save this plan as `docs/plans/M1-M4.md`, and update the docs
to match:
- README §19: the M1/M2 rows (the rig basics move to M1).
- README §6.1 and §16, CONTRIBUTING.md "Memory and performance", and the
  CLAUDE.md bullet: replace "never allocates / fixed-size arrays" with
  "minimise allocations without making code awkward; optimise when a profile
  shows the need". Perf tests become tracked benchmarks.

**Definition of done (every milestone):**
- `golangci-lint run` passes natively and with `GOOS=js GOARCH=wasm`, with no
  bare `//nolint`. Linters that prove too noisy are disabled only with a
  one-line reason.
- `go test -race ./...` passes, and the CI workflows are green.
- Exported identifiers have doc comments.
- The README and CONTRIBUTING are updated wherever the design changed.
- Conventional Commits, one or more per logical piece.

## M1: Core (`modernChip8` + `originalChip8`) and rig basics

**Goal:** a deterministic CHIP-8 core with few allocations that passes
Timendus tests 1–4, 6 and 7 headless on both platforms.

### Implementation

**`chip8/`** (standard library only; depguard enforces this)
- `platform.go`
  - The `Platform` enum with every id from README §6.3.
  - A fixed table of the default properties per platform: resolutions, ticks
    per frame, memory size, quirks. Each entry cites `platforms.json`.
  - `Platform.Implemented() bool`: only `ModernChip8` and `OriginalChip8` in
    M1.
- `quirks.go`: the `Quirks` struct (§6.2) and `DefaultQuirks(Platform)`.
- `machine.go`
  - `Machine` state:
    - memory as a `[]byte` sized for the platform by `New`/`Reset` (4 KB for
      CHIP-8), reused when the size doesn't change;
    - `V [16]byte`, `I`, `PC`, a 16-entry stack, `SP`, the delay and sound
      timers;
    - the keypad (current and previous state, for Fx0A);
    - the RNG state;
    - an error/halt state.
  - API from §6.2: `New`, `Reset`, `LoadROM`, `Poke`, `SetKey`, `RunFrame`,
    `Display`, `Sound`, `State`.
  - Sentinel errors: `ErrROMTooLarge`, `ErrUnknownOpcode`, `ErrStackOverflow`,
    `ErrStackUnderflow`, `ErrUnsupportedPlatform`.
  - Bad input never panics. The machine halts and `State().Err` reports why.
- `cpu.go`
  - `RunFrame`: tick the timers once, then run up to `TicksPerFrame`
    instructions. It stops early on halt, on the vblank quirk after `DXYN`,
    and while Fx0A waits for a key.
  - Dispatch is a `switch` on the top nibble: no function-value tables, no
    closures, no interfaces.
- `ops_base.go`
  - All 35 CHIP-8 opcodes as `opXXXX` methods. Each one cites its behaviour
    per platform.
  - Quirks: shift, memory increment (by X / leave I unchanged), wrap/clip,
    jump (BXNN), vblank, logic (vF reset).
  - vF is written after the result (correct when X = F).
  - Fx0A waits for a press **and** release; the timers keep running meanwhile.
  - Address arithmetic is masked to the platform's memory size.
- `display.go`
  - Plane buffers sized at `Reset` for the platform's largest resolution
    (64×32, one plane in M1). SCHIP and XO-CHIP add hi-res and a second
    plane later.
  - `DisplayView`: a small read-only value (width, height, `Pixel(x, y)`).
  - `DXYN` does XOR plus collision detection, clipping or wrapping by quirk.
- `fonts.go`: the small hex font at a named address (`FontAddr`), loaded on
  `Reset`.
- `rng.go`: xorshift64*, seeded from `Profile.Seed`. No `math/rand`.
- `trace.go`
  - The ring buffer of `{PC, Op, I, Frame}` (§6.4).
  - `EnableTrace(n)` allocates once; `Trace()` returns the buffer.
  - Recording stores raw values only.
- `disasm.go`
  - `Disassemble(p Platform, op uint16) string`, used only when someone views
    the trace.
  - "Dump trace on unknown opcode" support.

**`internal/testrig/`** (minimal)
- `Run(rom, profile, Script) chip8.DisplayView`, where a `Script` holds:
  - pokes, e.g. `0x1FF = n`;
  - key events: press key K at frame F, release at frame G;
  - a frame count.
- Golden frames: read and write `.txt` (`#`/`.`) and native-resolution `.png`.
- A pixel-exact comparison that reports a short ASCII diff in the test failure
  message.

**`cmd/golden-import/`** (minimal)
- Converts a suite picture (768×384, 12×12 blocks) into a 64×32 golden frame.
- Checks that every block is a single colour, and fails loudly otherwise.
- Maps the palette explicitly for pictures with three or more colours (e.g.
  `chip-8-logo.png`).
- In M1 it imports only the frames these tests need: `chip-8-logo`,
  `ibm-logo`, `corax+`, `flags`, `keypad-*`.
- Output goes to `testdata/golden/`.

**CI** (`.github/workflows/`)
- `ci.yml`:
  - checkout with submodules, Go 1.27;
  - `golangci-lint` for native and wasm;
  - `go test -race ./...` with a coverage report in the job summary;
  - `GOOS=js GOARCH=wasm go build ./...` (there is no `cmd/chippie` yet).
- `bench.yml`: on PRs, benchmarks on `main` vs the PR with `benchstat`,
  posted to the job summary. A slowdown over 10% is a warning, not a failure.

### Tests (all must pass at the end of M1)

- **Opcode tables** (`ops_base_test.go`): one table-driven test per opcode,
  with a row for each quirk that affects it. Each row sets the registers,
  runs one instruction and checks the result. Includes the edge cases:
  - vF as the destination;
  - carry and borrow at the boundaries;
  - BNNN vs BXNN;
  - FX55/FX65 under all three memory modes;
  - DXYN clip vs wrap at every edge, and collision detection.
- **Machine behaviour:**
  - timers tick once per frame;
  - Fx0A press-and-release, with the timers running during the wait;
  - vblank ends the frame after `DXYN` on `originalChip8` only;
  - stack overflow and underflow;
  - unknown opcode → halt with `ErrUnknownOpcode`;
  - `LoadROM` too large → `ErrROMTooLarge`;
  - unsupported platform → `ErrUnsupportedPlatform`.
- **Determinism:** the same seed and inputs produce identical display and
  state after N frames; a different seed changes the CXNN output.
- **Fuzzing:** `FuzzRunFrame`. Arbitrary ROM bytes never panic. A seed corpus
  in `testdata/fuzz` is committed.
- **Disassembler:** golden text per platform.
- **Screenshots** (`chip8/suite_test.go`, using the rig):
  - tests 1–4 on `modernChip8` and `originalChip8`;
  - 6-keypad modes 1/2/3, with scripted presses of keys 1 and 6;
  - 7-beep: press `B` and assert the buzzer state.
  - Each ROM's SHA-1 is recorded in the test table, so a submodule bump fails
    loudly.
- **Memory sizing:** `Reset` gives 4 KB on both CHIP-8 platforms and reuses
  the buffer on a same-size `Reset`.
- **Benchmarks** (`perf_test.go`, tracked, not failing):
  - `BenchmarkRunFrame/<platform>/<ticks>` (default ticks and 1000, running
    corax+), with `b.ReportAllocs()`;
  - `BenchmarkDXYN/lores`;
  - a trace-recording benchmark.
- **Golden import:** unit tests on synthetic images: two-colour conversion, a
  non-uniform block is rejected, palette mapping works.
- **Coverage:** `chip8/` aims for 90%+. It's reported in CI, not enforced.

**Done when:** all of the above pass in CI on GitHub.

## M2: Complete test rig and golden import

**Goal:** every 64×32 reference picture imported, readable failure diffs, and
test 5 (quirks) on the CHIP-8 platforms.

### Implementation

- **`cmd/golden-import`: every 64×32 picture.**
  - Adds `quirks.png` and `Cosmac-VIP-quirks.png` with palette mapping,
    `keypad-menu`, `beep.png` (used as a visual check alongside the buzzer
    assertion), and the lo-res `lores-*scrolling` pictures. The scrolling
    tests that use them are enabled in M5.
  - The HP48 `.JPG` photos and the non-test images (testimonials, splash,
    version) are skipped, with a reason printed.
  - Idempotent: running it twice gives byte-identical output, and its tests
    check that.
- **Failure output** in `testdata/failures/<test>/`:
  - `actual.png`;
  - `diff.png` (mismatched pixels in red over a dimmed expected frame);
  - `diff.txt` (an ASCII side-by-side).
  - Old failure output is cleared at the start of each run.
- **The `-update` flag** (`go test ./... -update`):
  - writes goldens only for cases with no reference picture (generated
    goldens);
  - refuses to overwrite imported ones;
  - prints which files changed, so they can be checked by eye.
- **The rig as a table:** one table of `{ROM, sha1, 0x1FF, platform, script,
  frames, golden}` drives all suite tests. M5 and M7 add rows to it.
- **Test 5-quirks** with `0x1FF = 1`, on `originalChip8` and `modernChip8`:
  - `originalChip8` is compared with the imported VIP quirks picture;
  - `modernChip8` uses an imported picture if one matches, otherwise a
    generated golden, checked by eye in the PR.
- **CI:** upload `testdata/failures/` as an artifact when tests fail.

### Tests

- **Rig self-tests:**
  - a deliberate mismatch writes all three failure files with the expected
    content;
  - golden round-trip: `.png` ↔ `.txt` ↔ `DisplayView`;
  - key-script timing: press and release land on the exact frames.
- **`-update`:** a generated golden is written into a temp dir; an imported
  golden is never overwritten.
- **golden-import:** every imported file matches the committed golden
  (detects drift); the skip list is explicit.
- **Suite:** 1–7 on both CHIP-8 platforms, all green.
- All M1 tests stay green.

**Done when:** all 64×32 goldens are committed, failure diffs are shown
working in a test, and test 5 passes on both platforms.

## M3: Ebitengine shell

**Goal:** native and browser builds play bundled ROMs at 60 TPS, with
keyboard, beep and the CRT shader, behind the loader page, deployed to GitHub
Pages. There is no TV art yet (that's M6): the CRT picture sits centred at 4:3
on a dark background.

### Implementation

- **Dependency:** `go get github.com/hajimehoshi/ebiten/v2@v2.10.6`, the
  version the prototype used. ebitenui waits until M4.
- **`cmd/chippie/main.go`:**
  - `ebiten.RunGame`.
  - Native flags: `-rom <path>`, `-platform`, `-shader clean|crt`,
    `-testroms <dir>` (default `third_party/chip8-test-suite/bin`).
- **`platform/`:** this milestone sets up the pattern.
  - `params_js.go` / `params_other.go`: URL query parameters (`?rom=`,
    `?shader=`) in the browser, and the flags natively.
  - Every `_js.go` file has a `//go:build js && wasm` tag and an `_other.go`
    stub.
- **`app/game.go`:** the `ebiten.Game`.
  - `Update`:
    - pauses when `!ebiten.IsFocused()` or while the picker is open;
    - reads the keys, calls `SetKey`, then `RunFrame` once;
    - polls async results with `select { …; default: }`.
  - `Layout` returns real pixels (outside size × device scale factor).
  - `Draw`: framebuffer → texture → phosphor → CRT, then the picker overlay.
  - The core-loop logic sits in plain functions, so it can be tested without
    Ebitengine.
- **`app/input/`:** the key map `1234/QWER/ASDF/ZXCV` → `123C/456D/789E/A0BF`
  as a table.
- **`app/sound/`:**
  - The audio context is created on the first user gesture. A
    "click or press a key to switch on" screen stands in for the power button
    until M6.
  - A square-wave `io.Reader` with a preallocated buffer, gated by an atomic
    "buzzer on" flag that `Update` sets from `machine.Sound()`. Fixed volume.
- **`app/crt/`:**
  - Ports `prototype/crt.kage` and `prototype/phosphor.kage`, using
    `//kage:unit pixels` and source coordinates
    (`srcPos - imageSrc0Origin()`), not `imageDstSize()` (lesson from README
    §3).
  - Go wrappers keep their `DrawRectShaderOptions` and uniforms as fields.
  - `CopyFramebuffer(DisplayView, []byte)` fills a reused pixel buffer for
    `WritePixels`.
  - Images are created at start-up or on resize only.
  - A "clean" mode (no CRT effect) for the browser tests.
- **`app/roms/`:** the bundled library.
  - `assets/roms/` holds the six CC0 `.ch8` files plus `bundled.json`, with
    title, file, SHA-1, platform, author and licence for each, compiled in
    with `go:embed`.
  - Test-suite entries:
    - natively, read from `-testroms`;
    - in the browser, fetched with `net/http` from `roms/test-suite/` (an
      `index.json` written by `build.sh`).
    - Loads run in a goroutine and report on a channel.
  - Games whose platform isn't `Implemented()` show as "coming soon" and
    can't be started.
- **Picker overlay:**
  - A simple list drawn with `text/v2` and Go fonts (`gofont`, BSD; recorded
    in `assets/LICENSES.md`; the period font comes in M6).
  - Keyboard up/down/enter and mouse click. The M4 library drawer replaces
    it.
  - Profiles come from `bundled.json`'s platform plus `chip8` defaults
    (`catalogue` arrives in M4).
- **`assets/LICENSES.md`:** entries for the six games (CC0, source URL), the
  Go fonts, and a note that the Timendus ROMs are GPLv3 and distributed
  separately.
- **`web/page.html`:** from the prototype.
  - Progress bar while downloading; unpack only if still gzip-compressed;
    start Go.
  - Removes the overlay completely with `[hidden]` / `display: none`.
  - Exposes `window.chippieTimings`.
- **`scripts/build.sh`**, adapted from `prototype/build.sh`:
  - WASM build with `-trimpath -ldflags="-s -w"`, then gzip and brotli;
  - inlines `wasm_exec.js` into the page;
  - copies `third_party/chip8-test-suite/bin/*.ch8`, its `LICENSE` and a
    source-link README into `web/dist/roms/test-suite/`, and writes
    `index.json`;
  - output goes to `web/dist/`.
- **`e2e/`:** Playwright.
  - `package.json` and a config for Chromium with `--use-angle=swiftshader`.
  - Desktop viewport, plus a phone viewport (390×844, DPR 2, touch).
- **CI:**
  - `ci.yml` adds `go build ./cmd/chippie` (native), the WASM build, and the
    Playwright smoke test.
  - New `pages.yml`: runs `build.sh` and deploys `web/dist` on push to
    `main`.
- **README §17:** record whether GitHub Pages compresses `.wasm` responses.
  If not, ship the pre-gzipped file (the loader already handles it).

### Tests

- **Unit:**
  - the key-map table covers all 16 keys, with no duplicates;
  - the sound generator: silent when gated off, correct period and amplitude
    when on, zero allocations per `Read`;
  - `bundled.json`: every file exists, its SHA-1 matches, every platform is
    known, and the "coming soon" set is exactly the unimplemented platforms;
  - the picker and core-loop functions: pause rules, and one `RunFrame` per
    `Update`;
  - the platform params stub.
- **Performance** (`app/crt/perf_test.go`): benchmarks for the framebuffer
  copy and the uniform update, with `b.ReportAllocs()`. Tracked, not failing.
- **e2e** (Playwright):
  - the loader finishes and is removed (clicks reach the canvas);
  - the canvas renders;
  - `?rom=test/2-ibm-logo&shader=clean`: sampled canvas pixels match the IBM
    golden;
  - a bundled game starts from the picker;
  - "coming soon" games can't be started;
  - the phone viewport renders.
- **Builds:** `go build ./cmd/chippie` and the WASM build in CI.
- **Manual checks**, written in the PR:
  - 60 TPS on desktop Chrome/Safari and an iPhone;
  - the beep sounds after the first gesture;
  - Glitch Ghost and Danm8ku are playable.

**Done when:** the Pages URL plays the CHIP-8 games and the test ROMs, and all
CI jobs are green.

## M4: Catalogue + library

**Goal:** the full game library from public archives. Metadata comes from the
embedded chip-8-database snapshot, refreshed in the background. ROMs are
downloaded, SHA-1-checked and cached in IndexedDB. There's a searchable
library drawer, a settings panel with per-ROM overrides, a file picker, and
drag-and-drop.

**First:** check the chip-8-database licence before embedding it. If it isn't
compatible with BSD-3 redistribution, stop and ask.

### Implementation

- **Dependency:** `go get github.com/ebitenui/ebitenui@v0.7.3`.
- **`catalogue/`** (standard library + `net/http`; no Ebitengine, no
  `syscall/js`)
  - `snapshot/`:
    - the chip-8-database files (`platforms.json`, `quirks.json`,
      `programs.json`, `sha1-hashes.json`) and chip8Archive's
      `programs.json`, compiled in with `go:embed`;
    - `SNAPSHOT.md` records the source commits.
  - `db.go`:
    - parses into typed structs once at start-up (allocation is allowed
      there) and indexes by SHA-1;
    - `Validate()` checks that the files parse, the schema is known, every
      hash points to a valid program, and every referenced platform exists;
    - maps the database's platform ids to `chip8.Platform`.
  - `merge.go`:
    - merges in the chip8Archive metadata (colours, tickrate, quirks);
    - chip-8-database wins on conflicts, and the conflicts are returned as a
      list for `catalogue-gen` to report.
  - `profile.go`: `Resolve(hash, overrides) chip8.Profile`.
    - Layers (README §7): platform defaults → ROM overrides
      (`platforms[0]`, `quirkyPlatforms`, `tickrate`) → user overrides.
    - Unknown hashes start from `modernChip8`.
    - Exposes the `colors`, `keys` and `touchInputMode` hints for the UI.
  - `sources.go`:
    - parses `sources.json` v1;
    - orders URLs so the original source comes first and `chippie` (hosted
      copies) last.
  - `refresh.go`: `Refresh(ctx, client, cache) <-chan Result`.
    - Fetches the latest chip-8-database JSON from GitHub in a goroutine.
    - Validates it, delivers the new DB on a channel (`Update` swaps it in),
      and caches it via `platform`.
    - Any failure keeps the snapshot or the cached copy.
- **`romstore/`**
  - `Get(ctx, hash) <-chan Result`:
    - checks the cache first;
    - then tries each URL in order, reading through
      `io.LimitReader(max+1)` to reject oversized files;
    - checks the SHA-1, and on a mismatch moves to the next URL;
    - stores the ROM in the cache on success.
  - Errors: `ErrHashMismatch`, `ErrUnavailable`. Cancelled by context.
- **`platform/`**
  - `storage_js.go` / `storage_other.go`:
    - IndexedDB, generalised from `prototype/storage_js.go` to `[]byte`
      values in `roms` and `metadata` stores;
    - the native version uses files under `os.UserCacheDir()/chippie`;
    - all calls are async, using channels.
  - `prefs_js.go` / `prefs_other.go`:
    - `localStorage`, safe when storage is blocked (falls back to memory);
    - the native version uses a JSON file in `os.UserConfigDir()`.
  - `filepicker_js.go` / `filepicker_other.go`:
    - a hidden `<input type=file>`, then `arrayBuffer()`, with the bytes sent
      on a channel;
    - the native version returns `ErrUnsupported` (use `-rom` or
      drag-and-drop instead).
- **`cmd/catalogue-gen/`**
  - Ports `scripts/coverage.py`:
    - fetches chip8Archive, kripod and the test suite at pinned commits;
    - hashes each ROM and matches it against the database;
    - writes `web/sources.json` (GitHub URLs pinned to commits) and a coverage
      report, including the metadata-merge conflicts.
  - The network code sits behind a `network` build tag; tests run on local
    fixture folders.
  - Delete `scripts/coverage.py` once its numbers are reproduced (README
    §9.1).
- **`.github/workflows/refresh.yml`:**
  - runs weekly and on demand;
  - refreshes the snapshot and `sources.json`, writes the coverage report;
  - opens a PR if anything changed.
- **`app/library/`** (ebitenui drawer)
  - Search `TextInput` that filters on every keystroke. `field.go` from the
    prototype goes into `app/ui/` as the IME fallback.
  - The list has a bounded height (README §3 lessons), plus a details pane:
    title, authors, release, description, platform, availability.
  - The six bundled games and the test-suite ROMs appear as library entries
    and load without a download.
  - **A pick closes the drawer.** Then:
    - the TV shows the "tuning…" static effect;
    - `romstore.Get` runs;
    - then `Resolve`, `Reset` and `LoadROM`.
  - Unavailable and "coming soon" states are shown.
  - The M3 picker is removed.
- **`app/settings/`** (ebitenui panel)
  - Platform dropdown (only implemented platforms can be chosen), quirk
    toggles, speed (ticks per frame).
  - "Reset to recommended" clears the ROM's overrides.
  - Trace view: disassembled on open, copyable; with the "dump on unknown
    opcode" option.
  - Overrides are saved per ROM hash in prefs.
  - The game pauses while the panel is open.
- **Local ROMs:**
  - a "load from device" button (file picker) and drag-and-drop
    (`ebiten.DroppedFiles`);
  - both hash the file, `Resolve` it and run it, with the size checked.
- **Startup:** start `catalogue.Refresh` in the background; the app works
  from the snapshot immediately.

### Tests

- **catalogue:**
  - the snapshot passes `Validate`;
  - `Resolve` against the real snapshot for known ROMs: platform,
    `quirkyPlatforms` override, tickrate, user override, unknown hash →
    `modernChip8`;
  - `chip8` defaults match the snapshot's `platforms.json` for implemented
    platforms (catches drift from M1);
  - the merge applies chip8Archive values and reports conflicts;
  - `sources.json` ordering and parsing errors;
  - `BenchmarkResolveProfile` (tracked).
- **Refresh** (using `httptest`):
  - valid → swapped and cached;
  - bad JSON, unknown schema, a broken cross-reference, HTTP 500 or a timeout
    → snapshot kept.
- **romstore** (using `httptest`):
  - SHA-1 mismatch → next URL;
  - all URLs fail → `ErrUnavailable`;
  - cache hit → no network;
  - oversized response rejected;
  - context cancellation;
  - a successful download is written to the cache.
- **platform:**
  - the native stubs work (storage round-trip in a temp dir, prefs survive
    when storage fails);
  - the `_js.go` files compile and lint under wasm in CI.
- **catalogue-gen:** a fixture folder → expected `sources.json` and report.
  There is no network in `go test`.
- **library and settings logic** (plain functions):
  - search normalisation and ordering;
  - availability state;
  - override → prefs → `Resolve` round-trip;
  - "Reset to recommended".
- **e2e** (Playwright):
  - typing filters the library (≥150 ms between keys);
  - a pick closes the drawer and the game starts (served by a local mock
    of the sources manifest);
  - IndexedDB restores a cached ROM after reload, with the network blocked;
  - "load from device" via `setInputFiles`;
  - drag-and-drop via a synthetic `DataTransfer` drop;
  - settings change a quirk and persist across a reload.
- All M1–M3 tests stay green.

**Done when:** the Pages build lists the library from the snapshot, downloads
and plays chip8Archive and kripod CHIP-8 games, plays them offline after the
first download, and supports local files and per-ROM settings. `refresh.yml`
has completed one successful run.
